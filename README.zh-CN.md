### Media Capture

简体中文 · [English](README.md)

Media Capture 将豆瓣、小宇宙、Apple Podcasts 的播客信息及 YouTube、Bilibili 的视频信息代入 Markdown 模板，通过写入规则追加到已有文件或新建文件，支持一行清单、每条一篇和每档节目一篇。默认每集一行，日记联动与作品清单关联均为可选功能。插件界面目前使用中文。

#### 安装

在 iPhone 或电脑上测试时，从 Obsidian 社区插件安装并启用 [BRAT](https://github.com/TfTHacker/obsidian42-brat)，添加测试插件仓库 `Ch1llNoodle/obsidian-media-capture`，选择已发布版本或预发布版本，然后启用 Media Capture。BRAT 在 Obsidian 内完成文件安装和后续更新。

插件要求 Obsidian 1.5.0 或更高版本。将 `main.js`、`manifest.json`、`styles.css` 放入 `<笔记库>/.obsidian/plugins/podcast-capture/`，在 **设置 → 第三方插件**中启用 **Media Capture**。从源码构建时，三个文件生成于 `release/podcast-capture/`。

更新时替换这三个文件，重新加载插件。保留原有 `data.json`，其中保存规则设置、输出索引、采集元信息和最近一次封面补全报告。

#### 采集媒体

1. 打开命令面板，运行 **Media Capture: 采集媒体**。
2. 粘贴播客或视频分享链接，选择**获取媒体信息**。
3. 确认节目／频道、标题、记录日期、状态和写入预设，选择**保存**。

状态包括 `听过`、`在听`、`想听`，只有听过条目保存收听日期。日期由使用者填写，插件不读取播放历史。启用日记联动后，从配置目录中的日期日记打开添加窗口，默认采用该篇日记的日期。

Apple Podcasts 使用单集分享链接；缺少 `i` 单集参数的节目主页不能作为单集记录。网页信息获取失败时，可手动填写名称；封面下载失败不阻止记录保存。

**打开媒体记录**打开配置的记录文件。**补全缺失封面**重新获取缺失图片，并报告失败阶段；已取得图片地址时，报告提供原图链接。

#### 视频记录与可选播放

视频集中清单与播客分开配置。新安装默认写入 `Videos.md`；旧中文路径默认使用播客清单同目录的 `视频.md`。两类清单共用行模板与追加标题，独立笔记和按节目／频道追加仍按各自规则执行。

支持 YouTube watch、shorts、live、embed、youtu.be 与 Bilibili 完整 BV／av 链接。Bilibili 保留分 P；短链需打开后复制完整地址。采集移除推广参数和起播时间，按整个视频或分 P 去重。元信息缺失时可手动填写。

“在 Obsidian 中播放”默认关闭。配置支持 `obsidian://mx-open` 的兼容播放器后，可主动开启；视频清单显示同名入口，模板中的 `{{mediaLink}}`、`{{mediaUrl}}` 同时启用。关闭后两变量对新生成或主动更新的内容为空，平台链接始终保留。播客平台页不是音频直链，不生成播放入口。播放和时间戳由外部播放器负责，Bilibili 需配置桌面网页播放环境。实际播放与手机视频采集仍需设备验证。

#### 模板与写入规则

所有输出共用单集信息和模板变量。每条写入规则选择内容模板、库内路径，以及“追加到文件”或“新建文件”。一次采集可执行多条已启用规则，共用一次封面下载和一个日记链接。

| 预设 | 目标位置 | 内容 |
| --- | --- | --- |
| 集中清单 | 播客写入 `Podcasts.md`，视频写入 `Videos.md` 的 Entries 下 | 每集一行 |
| 每条一篇 | 新建 `Podcasts/{{show}}/{{title}}.md` | 独立单集笔记 |
| 清单与独立笔记 | 同时执行上面两条规则 | 一行记录与一篇笔记 |
| 按节目／频道追加 | 追加到 `Podcasts/{{show}}.md` 的 Episodes 下 | 同一节目多集保存在一篇笔记中 |

在设置中应用预设，或逐条编辑名称、启用状态、写入方式、目录、路径模板、目标标题、模板文件、内置内容和封面宽度。可添加或移除规则，最多 20 条。应用预设替换规则配置，已有文件保留。添加窗口中的**使用已启用规则**执行配置的规则；选择某个预设则只覆盖本次选择。

固定路径将单集集中在一个文件中；`{{show}}.md` 按节目分组；`{{show}}/{{title}}.md` 配合新建方式可每条一篇。目录留空使用库根目录，缺少节目名时使用 Unsorted，不支持的文件名字符自动替换。新建方式找回已有同集笔记，遇到其他文件占用路径时增加单集标识后缀。追加方式复用目标文件，不存在时创建；已有文件须包含指定标题，标题留空则追加到末尾。多条已启用规则指向同一文件时，在写入前报错。

集中清单规则保留固定路径、目标标题，以及含 `{{link}}` 的单行列表模板，以兼容已有日记链接和作品关联。其他追加规则支持多行 Markdown，以 `podcast-entry` 注释界定各集的管理区域；应保留注释与块标识，手写内容放在区域外；实时预览在已跟踪的输出文件中隐藏这些管理标记。重复采集保留已完成区域，状态变化时若区域已经手工修改则停止写入并说明原因。

每条规则均可选择库内 Markdown 模板，模板文件留空则使用内置内容。新建模板可以带 YAML 属性，追加模板使用正文，不执行 Templater 或 JavaScript。

| 变量 | 内容 |
| --- | --- |
| `{{show}}`、`{{title}}` | 节目名与单集标题 |
| `{{fullTitle}}`、`{{link}}` | 合并后的“节目 · 单集”文本，或对应的 Markdown 单集链接 |
| `{{mediaLink}}`、`{{mediaUrl}}` | 兼容播放器 视频链接或协议地址；播客平台页为空 |
| `{{kind}}`、`{{consumed}}` | `video` 或 `podcast`，以及完成状态下选择的记录日期 |
| `{{url}}` | 规范化的平台单集链接 |
| `{{cover}}`、`{{coverPath}}` | 按规则宽度显示的本地 Markdown 图片，或其库内路径；没有封面时为空 |
| `{{published}}` | 平台提供的发布日期 |
| `{{listened}}` | 听过状态下选择的收听日期，其他状态为空 |
| `{{currentDate}}`、`{{date}}` | 首次生成该单集记录时的本地日期，更新模板时保留 |
| `{{description}}` | 已取得的平台描述，或手动填写的文字 |
| `{{state}}`、`{{provider}}`、`{{id}}` | 状态、平台和稳定单集标识 |

日期支持 YYYY、MM、DD，例如 `{{published:YYYY-MM-DD}}`。路径可用 show、title、published、listened、currentDate、date、provider、id，子目录之间使用普通斜杠。缺失的可选信息在正文中留空，在文件名中使用 Untitled。封面宽度为 16～600 像素，预设行记录为 24，单集内容为 120。

一行模板可以使用 `- {{listened}} {{cover}} {{link}}`；多行追加模板可以包含标题、链接、描述和自定义章节。新建文件的 Markdown 模板可以带属性：

```markdown
---
show: "{{show}}"
published: "{{published}}"
listened: "{{listened}}"
tags: [podcast]
---
### {{title}}

{{cover}}

[单集链接](<{{url}}>)

#### Notes

#### Quotes
```

**创建媒体笔记**命令以每条一篇预设打开添加窗口。清单行旁的**写笔记**固定使用该集，**打开笔记**找回其主要单集笔记；清单还保留第一个额外输出的链接，选择按节目／频道追加时可链接到节目文件。阅读模式与编辑器均提供行内入口，不需要快捷键。作品关联和基于清单的追踪仍使用集中清单规则，其他输出文件不会自动加入外部追踪工具的统计。

新建文件保留 `podcast_capture_id`，额外的新建规则使用 `podcast_capture_rule` 区分同集的多个输出，原主要笔记保留已有标识。追加索引跟随文件改名；已跟踪文件或管理区域消失时，保存会说明缺失位置，不在其他位置重新创建。跨设备使用时将 data.json 与笔记库一并同步。

#### 将模板应用到已有记录

修改模板默认用于新增记录。设置中选择**将模板应用到已有记录 → 预览并选择**，或运行同名命令，可预览更新并选择文件。

新建方式的输出重新生成全文，包括属性和手写区域；追加方式只替换对应条目或管理区域，保留外围正文、作品子项和摘抄。同一节目文件内的多集内容合并为一次更新和一次备份，文件名与位置不变。

每个文件替换前，在原文件旁保存并校验带时间戳、后缀为 `.podcast-capture-backup` 的完整文本备份。结果中的**查看备份**直接在 Obsidian 内显示原文，将原文复制回笔记即可恢复；确认不再需要原文后再清理备份。

采集元信息保留原日期和描述，笔记中明确填写的属性优先。旧笔记从本地链接、标题、属性和清单恢复可用信息，缺失的可选字段在预览中列出；缺少必要链接、重复标识、原规则被移除或区域标记损坏时，说明原因并跳过。更新模板不发起网络请求。

报告逐篇列出路径、失败阶段、原因、更新状态和备份位置。预览后被编辑的文件跳过，备份失败不替换原文，其余所选文件可继续处理。内容相同时不新增备份，关闭已启动的窗口不取消排队中的更新。

#### 关联作品与播客

先在豆瓣标记想读、想看等状态，通过自己的豆瓣同步工具将作品导入 Markdown 清单。在设置中把书籍、电影、电视剧、音乐、游戏和舞台剧路径指向已有清单；默认路径位于 `Recommendations/`，插件只读取已存在的文件。

在播客记录的编辑模式或阅读模式中选择单集旁的**添加关联**。窗口固定使用该单集作为来源，从作品下拉框选择想读、想看、想听或想玩的作品，填写可选摘记，再选择**保存关联**。窗口不提供搜索框或来源播客选择框，进行中、已完成及未标记状态的作品不列入选项。**打开媒体关联入口**命令打开媒体记录页。

作品行追加来源单集的块链接和摘记，关联作品的链接及摘记在对应播客下方按缩进子列表显示，不加“推荐”标签，内部管理标记使用行内注释，不再单占两行。实时预览只在播客记录中隐藏状态、作品管理注释和单集块标识；源码模式保留原始 Markdown。作品清单的显示由 Obsidian 样式或其他工具独立管理。阅读视图对子列表单独设置换行与缩进，保留名称、日期、状态及封面。同一来源重复保存不会重复追加，多个来源保存在同一作品行。关联过程完全在本地进行，不搜索豆瓣、不请求作品详情、不下载作品封面，也不创建作品文件、待看条目或日记属性。保存前重新检查作品及来源是否仍存在。两篇笔记分别更新；第二次写入失败时明确提示已保存的一侧，再次保存可以补全且不会重复。插件在工作区就绪后从已有作品侧关联补回播客行链接，后来已完成的作品也会继续显示。

作品清单使用单行 Markdown 列表，例如：

```markdown
- [作品名称](<https://movie.douban.com/subject/123/>) <!-- douban-state: 想看 --> <!-- douban-type: movie --> ^douban-123
```

`douban-type` 可使用 `book`、`movie`、`teleplay`、`music`、`game`、`theater`，缺省时采用该清单配置的类型。可选工作区事件 `podcast-capture:recommend` 接收 `{ path, blockId }`，打开窗口并选中该来源播客；`supportsRecommendations` 表示接口可用。

自定义同步脚本需要在同一作品的新行中保留 `podcast-sources:start` / `podcast-sources:end` 之间的来源信息。豆瓣收藏同步由外部工具负责。

#### 设置

| 设置 | 默认值 | 行为 |
| --- | --- | --- |
| 写入规则 | 启用集中清单 | 使用预设，或分别配置追加与新建规则 |
| 封面目录 | `image/podcasts` | 各规则共用本地封面目录 |
| 保存本地封面 | 开启 | 采集或补图时下载缺失封面 |
| 启动时补全封面 | 关闭 | 工作区就绪后补全集中清单的封面 |
| 日记联动 | 关闭 | 将听过单集链接写入唯一匹配的已有日期日记 |
| 日记目录／属性 | `Daily`／`podcasts` | 搜索子目录，保留其他属性 |
| 作品清单路径 | `Recommendations/` 下的 `Books.md`、`Movies.md`、`Series.md`、`Music.md`、`Games.md`、`Theater.md` | 已有的想状态作品清单 |

日记联动不创建日记。执行集中清单规则时使用清单块链接，否则使用第一个额外输出，节目文件的链接包含单集定位。从已有清单行创建笔记时沿用原活动来源。修改规则路径作用于新增输出，不移动已有文件。

#### 记录标识与补图

补全封面时，若旧记录误存了通用 Apple 网页播放器标题，且取得了精确匹配的单集信息，会同时修正该标题；手写名称、原日期、块标识和摘抄保留。

插件自动附加状态注释、已听过条目的日期注释和 Obsidian 块标识，用于去重、补全封面及日记链接。手动编辑时保留这些标记。单集行之外的笔记和摘抄保留原样。

同平台按单集编号去重；跨平台只有完整的“节目名 · 单集名”经过大小写、空白和 Unicode 规范化后相同时，才复用原记录。已听过记录保留首次日期。记录另一日重听时，需要启用日记联动，并确保该日期已有唯一一篇日记；原记录行继续保留。

#### 笔记库集成与迁移

输出为普通 Markdown，Dataview 等追踪插件为可选组件。保存后发出 `podcast-capture:updated` 工作区事件，包含 `path`、`blockId`、`state`、`date`；保存笔记时另有 `notePath`、`output`，没有清单行时 `blockId` 为空。载荷类型由 `src/types.ts` 中的 `CaptureUpdatedEvent` 定义。只读取清单的追踪工具不会自动统计独立笔记。

尚未支持可配置设置的旧安装，在没有已保存设置、且旧记录文件存在时执行一次路径迁移。已有设置优先。旧 `douban-state` 注释和块标识继续兼容。

0.6.x 的设置在内存中转换为等效规则，保留路径、模板和输出选择；编辑规则后保存统一的 `writeRules` 配置。旧 `captureMode`、`rowTemplate` 和单集笔记字段继续作为兼容输入，设置页直接编辑规则。旧行模板中的 `date`、`title` 分别映射为 `listened`、`fullTitle`，保持原有含义。部署不覆盖个人 data.json。

#### 开发与检查

运行源码全部使用 TypeScript。编译器启用 `strict`、索引访问检查、显式覆盖检查和未使用声明检查，关闭 JavaScript 源码接入。ESLint 在运行代码中禁止显式 `any`，并检查不安全的赋值、传参、调用、成员访问和返回。持久化数据与第三方 JSON 以 `unknown` 进入，在使用前完成类型收窄。

`src/main.ts` 管理生命周期和命令；`capture-output.ts` 执行统一采集流程，`capture-context.ts` 每次采集集中处理封面与日记链接。`write-rules.ts` 校验规则并解析预设，`note-format.ts` 渲染共享变量，`episode-notes.ts` 和 `append-output.ts` 分别处理新建与追加目标。`refresh-plan.ts` 按文件规划模板更新，`note-refresh.ts` 执行备份与替换。服务、设置页、平台解析和库操作分别保留独立职责，共享类型位于 `types.ts`。

```sh
npm ci
npm run typecheck
npm run build
npm test
npm run lint
```

生产构建将运行代码打包为 `release/podcast-capture/main.js`，并在同目录暂存 manifest 和样式。测试使用 esbuild 编译 TypeScript 模块，再通过模拟的 Obsidian API 验证行为。可选的追踪视图兼容测试由 `PODCAST_TRACKER_TEST_PATH` 指定脚本路径；未设置时跳过该项。`PODCAST_DOUBAN_SYNC_TEST_PATH` 可另外指定自定义豆瓣同步视图，验证来源保留与状态合并。

发布文件为 `main.js`、`manifest.json`、`styles.css`。源码仓库忽略生成的构建文件、依赖目录及个人 `data.json`。依赖安全检查使用 `npm audit`，与编译、功能测试分别执行。

推送与 manifest、package 版本一致的标签后，发布工作流执行构建、测试和 ESLint，上传运行文件并发布可供 BRAT 安装的 GitHub 预发布版。该流程不提交 Obsidian 社区商店审核。

#### 本地开发与部署

源码仓库与安装目录分开管理；源码位于笔记库内时，在外层 Git 仓库忽略源码目录，运行文件和个人配置继续随笔记库备份。`release/podcast-capture/` 保存生成的安装文件，笔记库安装位置仍为 `.obsidian/plugins/podcast-capture/`。

将 `.deploy.example.json` 复制为 `.deploy.local.json`，把 `vaultPath` 设置为已有笔记库的绝对路径。执行 `npm run deploy` 完成构建和运行文件复制，然后在 Obsidian 中重新加载插件。`npm run deploy -- --vault /absolute/path/to/vault` 可覆盖本机配置，也支持环境变量 `PODCAST_CAPTURE_VAULT`；取值优先级为命令参数、环境变量、本机配置。

部署只复制 main.js、manifest.json 和可选的 styles.css，保留 data.json 及其他安装文件；写入前核对插件 ID 和构建版本，拒绝部署到源码仓库或通过符号链接安装目录写入。本机部署配置和 release 产物不进入 Git。`npm run dev` 监听源码并更新构建目录，不自动部署。

#### 网络访问与移动端

YouTube 元信息通过 `www.youtube.com/oembed` 获取，Bilibili 请求公开视频页。豆瓣和小宇宙的元信息请求发送至单集公开页面。Apple Podcasts 优先使用 `itunes.apple.com` 的公开 iTunes Lookup API，按分享链接中的单集编号和地区精确匹配，再回退单集网页，不使用 Apple 登录态或令牌。节目目录每次最多查询 200 集，较早单集可能需要网页回退或手动填写名称。封面仅从 `doubanio.com`、`xyzcdn.net`、`mzstatic.com`、`ytimg.com`、`hdslb.com` 及其子域通过 HTTPS 下载。即使手动填写名称，保存时也可能请求缺失封面；关闭本地封面下载后，不再发起图片下载请求。手动补图和可选的启动补图也会按需请求单集页面。作品与播客的关联仅访问已配置的本地清单，不发起网络请求。

运行代码使用 Obsidian API 和标准 Web API，不依赖 Node.js 或 Electron。manifest 允许 Android、iOS 加载，尚未完成真机兼容性验证。插件不读取平台登录凭据或播放历史，不包含遥测。平台或网络错误会显示在添加窗口或补图报告中。

封面缓存不依赖平台或节目名。同一图片地址缓存命中时复用已有文件；新地址下载后逐字节核对封面目录中的同大小图片，包括旧版按单集命名的文件。完全相同则复用，不改名、不删除旧文件；内容不同则分别保留。同图被平台重新压缩、裁切或缩放后不会自动合并。节目身份与封面复用分开处理，共享封面不会合并单集。

新封面采用可读名称：播客优先使用节目名，视频使用标题；节目名缺失时使用记录标题。文件名中的不合法字符替换为下划线。同名且图片内容不同时加八位短后缀，相同图片仍复用已有文件，封面指纹不再作为完整文件名。
